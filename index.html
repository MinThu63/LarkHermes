What it does

Ask anything the wiki covers

Team knowledge lives in a wiki that is slow to search and easy to misremember. People ask in chat and get a stale answer, or hunt for the page themselves. LarkHermes searches the whole wiki for you and replies in your private message with the answer and the source pages.

Verifiable by design

Links are pasted exactly as they appear in the wiki. If a link can't be copied accurately, the bot leaves it out instead of guessing.

Grounded, never invented

If the wiki says one thing and public sources say another, the wiki wins. If two pages disagree, both are shown under their own headings.

Private by default

Answers arrive in a direct message. No channel or thread to keep track of.

How a question is handled

Find first, then answer

The assistant decides whether the question belongs to the wiki. If it does, it answers from the pages it found and cites them. If not, it answers from general knowledge and shows no wiki links.

Architecture, simplified

Three layers

A general view of how the pieces fit. Deployment details are intentionally left out.

ANSWERING

Runs on every question

Finds relevant pages, checks the evidence is good enough, then writes a short answer with sources.

MEASURING

Runs separately, read-only

Studies past conversations without touching the live assistant, so it can be added or removed safely.

Keeping answers current

Built on a refreshed copy of the wiki

Fast

Answers come from the local copy, so searching does not wait on the wiki.

Safe on failure

If a refresh comes back empty, the last good copy is kept and an alert is raised.

Backup search

A simple keyword search takes over if the relevance check is unavailable.

Quality

The assistant measures itself

Each failed answer gets a root cause, so the next step is clear: write a missing page, fix search, or adjust the instructions.

Five layers of offline evaluation

The evaluation reads the saved conversation record only, so the live assistant carries no extra code.

LAYER 1

Turns

Every query, search, retrieved page and response time as structured records.

LAYER 2

Metrics

Citation rate and response time, with week-over-week change.

LAYER 3

Human review

A weekly report with a scoring screen. Sampled turns include every 👎 and every empty search. Scores feed the next report.

LAYER 4

Failures and benchmark

Six-category failure labels on every turn, plus a fixed question set that gives each change a before and after.

LAYER 5

Fix list

The week's top failure categories linked to concrete fixes.

Six kinds of failure

Retrieval search missed it · Knowledge gap page missing · Planning should have searched · Reasoning found pages, didn't use them · Hallucination cited something not retrieved · System error or no response

What gets tracked

How often answers carry a source link, response time, and whether a fixed set of benchmark questions finds the right pages.

👎 is the feedback button

A thumbs-down reaction flags an answer for review. No separate form.

A weekly digest

A short report shows the trend and the topics where the wiki needs better content.

Design choices

Why it is not a typical bot

Configured, not hand-coded

It is a declarative agent profile on a native chat gateway, with instructions, a few skills and scheduled jobs. It replaced an earlier hand-built bot after several rewrites.

Search and writing are separate

One step decides which pages matter and the model only writes the answer. That makes results easy to debug and to benchmark. No vector database is needed.

Users shaped the format

The team rejected plain link dumps, so answers are conversational with sources. Each rewrite taught a product lesson.

A quality loop, not ship and drift

A regression benchmark, a label on every failure and a weekly human review give the chatbot something close to a testing culture.

Wiki is the source of truth

The model falls back to general knowledge only when the wiki has nothing, and it has to say so.

Cheap feedback

A 👎 reaction writes one log entry and gets a silent reply. No form, no extra message.

Dependable and careful

Run as a dependable service

Always on

Runs as a managed service that restarts itself, with scheduled health checks.

Degrades gracefully

If a component is unavailable, the assistant falls back to a simpler path instead of failing silently.
